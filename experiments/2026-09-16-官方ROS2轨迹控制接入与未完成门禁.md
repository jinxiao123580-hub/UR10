## 工厂标定提取故障与解决

官方 `ur_calibration calibration_correction.launch.py` 持续报告
`Stream is invalid`。独立 TCP 读取确认 `192.168.1.3:30001` 立即返回
URControl 3.15 数据；`strace -e connect` 进一步证明失败程序一次 TCP `connect()`
都没有调用，排除了机器人拒绝连接和网络超时。

安装版本为 `ur_calibration/ur_robot_driver 2.14.0`，但
`ur_client_library 2.15.0`。官方 Driver 2.14 标定源码只调用
`pipeline.run()`，未先调用接口规定的 `pipeline.init()`。Client Library 2.14
的旧重连逻辑会从未连接状态调用 `connect()`，因而掩盖了这个遗漏；2.15 将首次连接
与断线重连分开，`Invalid` 状态不能直接 `reconnect()`，形成无限重试。

在官方 2.14.0 源码中加入一行 `pipeline.init();` 后，仅重编译
`ur_calibration`。修补版在约 `0.4 s` 内成功读取 `calibration_status: 2`，输出
六组 checksum 原始值并写入 `config/ur10_factory_calibration.yaml`；最终 hash 为
`calib_15120592593058779304`。补丁保存在
`patches/ur_calibration-2.14-client-2.15-pipeline-init.patch`。

工厂标定文件现已取得，但仍需在官方驱动启动日志中看到
`Calibration checked successfully`，并用真机只读 TCP/FK 对比复核，才能把该 YAML
标为完成验收。当前仍不能声称碰撞模型已经通过。

上述独立验收随后完成：官方驱动连接 URControl `3.15.8.0` 后报告 checksum
`calib_15120592593058779304`，与 YAML 完全一致，并明确输出
`Calibration checked successfully`。启动参数为 `headless_mode=false`、
`activate_joint_controller=false`，没有运行示教器 External Control 节点，没有发送
运动程序。

使用工厂标定生成官方 URDF 后，从 11170 帧示教轨迹每 100 帧抽取一次，共 112 个
姿态做离线 FK 对比。正确的 `base→tool0` 相对控制器 TCP：位置误差中位数
`0.015613 mm`、P95 `0.016859 mm`、最大 `0.017312 mm`；姿态误差中位数
`0.003969°`、P95 `0.004526°`、最大 `0.004694°`。错误使用 `base_link` 时则约为
`1.182 m / 180°`，再次确认后续规划和验收必须使用 `base`。
