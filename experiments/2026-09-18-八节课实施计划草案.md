## 2. 三个阻塞与解决顺序

现在真机运动整体被禁用，根因有三个，彼此耦合：

- **阻塞 A · 负载（payload/CoG）未独立测量** → 影响第 3、4、6 节全部真机运动
- **阻塞 B · 重力补偿全部 `valid: false`** → 影响第 5 节力觉、第 8 节力控
- **阻塞 C · 时延与时间同步完全没做** → 全库检索 `延迟|时延|latency|时间同步|时间戳对齐` 零命中；而第 5 节明确要求"特别注意数据时间上的延迟"

### 关键认识：A 与 B 是同一套物理量

工具链为 `法兰 → ATI 力传感器 → [偏心相机] + [正装夹爪]`。重力补偿要辨识的
（末端质量 m、重心 r）与 UR `set_payload` 需要的（质量、重心）**是同一组参数**。
一次规范的静力学标定应同时解开 A 和 B，不应做成两件事。

## 3. 必须先做的三项前置实验（P0）

### P0-0 · 第 6 节 35.84 mm 的算术快查（30 分钟，最高性价比）

**发现**：50 mm 立方体半边长 25 mm，`√(25²+25²) = 35.36 mm`，与实测 **35.84 mm** 只差
0.48 mm —— 正好等于你们标定/点云的亚毫米残差量级。

若真的"只用**单个**可见侧面 + 沿其法向偏半边长"，期望误差应是 **25 mm（单轴）**，
不是 35.36 mm。所以高度提示：**候选中心在水平两个轴上各偏了一个半边长**
（可见区域实际是**两个相邻竖直侧面的并集**的质心，或半边长偏移被施加到了两个轴）。
这属于**几何方案/定义错误，不是精度不够** —— 先验证这条，比调任何标定参数都值。

**怎么做**：打印"视觉候选中心 − 人工确认抓取中心"的**差向量**（不是只报模长 35.84 mm），
检查是否 ≈ `(±25, ±25, 0)` 或 `(0, 0, ±25)`。差向量的方向直接指出错在哪一步。

**正确算法（单视角只有 1–2 个侧面时）**：
聚类 → RANSAC 取最大平面 → 判定是否**顶面** → 顶面法向 `n̂` + 内点 → 投影到平面 →
2D 凸包 → **最小面积外接矩形**（rotating calipers）→ 得边长 `(a,b)` 与矩形中心 `c_foot` →
**验收 `(a,b) ≈ (50,50) mm ± 2 mm` 且覆盖率 > 85%，否则判退化拒识** →
**中心 = `c_foot − (h/2)·n̂`**。侧面**只用于约束 yaw / 交叉验证**，不得单独推中心。

### P0-1 · 力标定的 2 倍质量矛盾 ★最高优先

**发现**：仓库所有独立拟合的末端质量高度一致地收敛到 **3.20–3.29 kg**
（3.217 / 3.2223 / 3.2222 / 3.2119 / 3.2025 / 3.2947 / 3.2257 kg，横跨 6 次不同采集批次）；
但 2026-09-10 的**单姿态** `|F|/g` 独立反推为 **6.56 kg**（`F=(0.39,11.15,63.36) N`，`|F|=64.4 N`）。

两者相差 **2.03 倍**，且拟合结果极度可重复 —— 这说明误差是**系统性的**，
不是噪声、不是姿态覆盖不足、也不是条件数问题（条件数 8.2–9.1 一直在门限内，
残差却有 2.0–15.4 N）。

**为什么这是第一优先**：一个 2 倍量级的系统性错误会让此后所有数字失去意义 ——
包括"力 RMS ≤ 1.0 N"这类验收门限本身、任何力控增益、以及 UR 负载参数。
这也能解释为什么"每加一个新独立姿态就出现 2 N 反例"：模型尺度不对，
在某些姿态方向上的偏差必然放大。

**怎么做**（只读，不动机械臂，约 1 小时）：
1. 在**至少 3 个差异大的静态姿态**记录 `/ft_sensor/wrench_raw`，每个姿态等待静止，
   计算 `|F_raw|`。若无外力，`|F_raw|` 应**与姿态无关**且等于 `m·g`。
   - 若三个姿态的 `|F_raw|` 都 ≈ 6.5·g → 拟合设定错误（旋转约定/坐标系）
   - 若都 ≈ 3.2·g → 2026-09-10 那次测量被高估 2 倍
2. 核对 `scripts/ati_netft_node.py` 中的换算常数：源码里是**硬编码默认值**
   `DEFAULT_COUNTS_PER_FORCE = 1_000_000.0` 与 `DEFAULT_COUNTS_PER_TORQUE = 1_000_000.0`。
   必须与**该传感器的实际标定文件/量程**一致，否则所有用力值表示的结论
   （含 1.0 N / 0.1 N·m 门限）单位都是错的。
3. 复核 ATI 硬件 Bias（应为六路全零）与软件 Tare 的取值姿态 —— 仓库历史中
   记录过一次"错误写入 Bias 导致**读数翻倍**"的事故，2 倍现象在本系统上确实出现过。

**判据**：三个以上姿态的 `|F_raw|/g` 一致，且与多姿态拟合质量一致（相对偏差 < 5%）。
**产出**：`outputs/ft_calibration/mass-scale-diagnosis-<日期>.json` + 结论写入 `docs/12`。

### P0-2 · 时延测量与时间对齐（阻塞 C）

第 5 节要求"特别注意数据时间上的延迟"，仓库从未做过。至少需要测量并记录：
- ATI：RDT 采样 → 驱动发布消息 `header.stamp` 的时延
- UR：30003/30013 状态帧的产生时刻与时延
- 两路数据做姿态-力配对时的对齐误差

**做法（待检索确认最优方案）**：用机械臂做**已知频率/幅值的正弦姿态激励**，
对力信号做互相关求相位差 → 反推时延；或用阶跃（快速敲击/快速停）响应。
**判据**：给出时延数值与不确定度，并证明对齐后重力残差显著下降。
**产出**：`outputs/latency/` + 时延结论写入 `docs/12`。

> 注：P0-2 与 P0-1 很可能相关。示教播放那批数据是在**运动过程中**取静态窗口的，
> 若姿态与力采样时刻有偏移，等效旋转就会错，拟合质量会被系统性地压低 ——
> 这与观察到的"拟合质量只有单姿态反推的一半"方向一致。

### P0-3 · 负载质量与重心的独立测定

第一阶段的 8.0 kg 来自"实测工具 6.56 kg + 传感器自重估算 1.5 kg"，其中
6.56 kg 正是 P0-1 中被怀疑高估 2 倍的数；控制器当前回读为 `3.5 kg / [0,0,0.1] m`。
三个数不一致，必须定出一个可信值。

**做法**：
- 优先使用示教器「安装 → 负载」向导（仓库 `experiments/2026-09-10` 记录其存在，
  但 `HANDOVER.md` 称 CB3 无 Measure 按钮 —— **这两处矛盾需现场确认**）
- 或者：用 ATI 的静态多姿态**同时**辨识末端质量、重心与安装旋转
  （`calibrate_ft_gravity.py` 已有该能力，但需先用 P0-1 修好尺度）
- 写入控制器后用 `verify_ur_payload.py` 回读确认

**判据**：质量与重心至少由两种独立方法给出一致结果（相对偏差 < 5% / 重心 < 10 mm）。
**产出**：`config/` 负载参数 + 写入 `docs/11`、`docs/14`。

### 第 4 节 · 关节标定 + 100.5 mm 直线
- **做**：
  1. `python3 scripts/calibrate_fingertip_tcp.py --samples 12 --holdout 3 --duration 1`
     —— 只读，用示教器把闭合左指尖对准固定参考点，多姿态采集
  2. 通过条件数与留出残差门限后，用**同一空间固定点复核不同姿态下指尖一致性**
  3. 把 TCP 写入控制器（示教器 安装 → TCP），使 30003 的 `tool_vector_actual` 变为指尖位姿
  4. **100.5 mm 直线实验**：扩展 `ur_relative_movel.py`（其 `--max-distance` 默认 30 mm，
     需放宽到 0.11 m），沿基坐标水平移动 100.5 mm，落笔划线，用尺测量
- **⚠️ 几何要点（必须写进讲义）**：纯平移的 `movel` 下，TCP 定义误差**不会**改变笔尖的
  位移量 —— 刚体平移与参考点无关。所以"用尺量 100.5 mm"检验的是**运动学/定位精度**
  （工厂运动学、编码器、负载引起的伺服变形、笔纸接触），而**不是** TCP 定义。
  TCP 定义影响的是**姿态变化时**笔尖的位置（后续笔画、抬笔落笔），
  以及下压量/接触力是否可控 —— 这一点要在实验设计里分开验证。
- **判据**：多姿态固定点一致性残差 + 尺量结果与 100.5 mm 的偏差记录
- **产出**：TCP 参数写入 `docs/11`；`outputs/` 保存划线照片与测量记录

### 第 6 节 · 视觉自动抓取
前置：第 3、4、5 节完成

- **产出**：`scripts/` 定位与抓取脚本 + 实验记录

## 5. 风险与延后项

- **第 7 节（转盘动态抓取）的硬件风险**：现有 Mech-Eye PRO XS 为结构光相机，
  典型采集时间 0.7–1.1 s，且 SDK 只有单次阻塞的 `capture2D()`，**没有任何连续/流式 2D 接口**。
  但发现一个关键开关：`Scan2DFlashAcquisitionMode`
  - `Fast`（多数型号的默认）：2D 图作为 3D 采集的一部分 → `capture2D()` 也得等 3D 采完
  - `Responsive`：2D 图独立采集 → `capture2D()` 才真正独立，仅受 2D 曝光时间限制
  因此**第 7 节的第一个动作应是实测 `capture2D()` 在 `Responsive` 下的真实帧率**，
  再决定是否必须新增相机。在拿到这个数字前，不应假定需要采购。
- **第 8 节（毛笔字）** 依赖第 4 节 TCP 与第 5 节力控；力控未通过验收前不得启动。
- 全库检索确认：**RTDE 从未使用过**（仅 30003/30013 @125 Hz）。若第 7 节需要更高频率
  与更好时间戳，RTDE 是候选（**CB3 上的可用性与频率上限待检索确认**）。
