## 1. 负载标定（⚠️ 需你确认一件事）

### 实测数据（力传感器）

```
静态力:   F = (0.39, 11.15, 63.36) N   →   |F| = 64.4 N
静态力矩: T = (1.87, 2.02, -0.00) N·m   →   |T| = 2.75 N·m
工具侧质量 ≈ |F| / 9.81 ≈ 6.56 kg
力臂 ≈ |T|/|F| ≈ 43 mm（传感器原点 → 下方工具重心）
```

### 现状问题

安装文件里 `toolPayload = 0.01 kg`，与真实负载差 **600 倍**。
UR 轨迹规划按 0.01kg 做惯性补偿 → 大负载下精度/动态性能受影响。

### 🔴 需要你确认：**ATI 力传感器是不是装在 UR10 法兰上？下面挂着什么？**

- 若是：机器人负载 ≈ **传感器自重 + 6.56 kg**（传感器自重查铭牌/规格，约 1~2 kg）
- 若不是（比如传感器单独在台架上）：机器人负载就是夹爪/相机那套，另算

### 标定方法（确认后执行）

```urscript
set_payload(8.0, [0.0, 0.0, 0.05])     # 质量 kg + 重心(tool0 系,米)
```

- 通过 30002 注入立即生效；要持久化需改 installation 文件或每次程序开头调用
- ⚠️ URScript 程序每次运行会重新 `set_payload`（示例程序里有 `set_payload(0.01)`），
  **必须在我们自己的注入脚本里也设置**（`ur_arm.py` 的 `send_script` 可加）
- 重心精确值：用示教器「负载」向导（要动机械臂）或从力矩差推算

## 2. 力传感器置零（⚠️ 进行中，交接给 Codex）

### 过程与教训（含我犯的错）

1. 读应变片：`G = [6033, 1398, -2080, -717, 2907, -311]`，Bias 原全 0
2. **POST 会 400**：表单 `setting.cgi` 默认是 **GET**
3. GET 写 `bias = -G` → 成功（302）但**读数翻倍**（Fz 63→128N）
   → 实测公式 **`output = gage − bias`**，**要清零必须 `bias = +G`（正号）**
4. 写正确符号时连接断了，**ATI 盒子从此不可达**（大概率 2009 固件网页服务被打挂）

### 正确步骤（Codex 执行中）

```bash
curl -s http://192.168.1.2/manuf.htm | grep -oE "HighlightRed\(-?[0-9]+\)" | head -6
curl -s -G "http://192.168.1.2/setting.cgi" \
  --data-urlencode "setcfgsel=15" --data-urlencode "setuserfilter=1" --data-urlencode "setpke=1" \
  --data-urlencode "setbias0=6033"  --data-urlencode "setbias1=1398" \
  --data-urlencode "setbias2=-2080" --data-urlencode "setbias3=-717" \
  --data-urlencode "setbias4=2907"  --data-urlencode "setbias5=-311"
# 验证：Bias Values 应变成本组值；RDT 读六轴 ≈ 0
```

> ⚠️ 置零姿态有讲究：**在最终工作姿态**下做；换姿态/重装后重做。
> 备选：软件层 `ros2 service call /ft_sensor/tare std_srvs/srv/Trigger`（只影响本节点）。

## 3. TCP 工具中心点标定（🛠 工具就绪，等你现场配合）

### 工具

`scripts/tcp_calib.py` —— 球拟合法（算法已用合成数据验证，误差 3e-17 m）：

```
原理: 工具尖端戳固定点 P，多姿态下 P = R_i·t + d_i，
      两两相减消去 P → (R_i−R_j)·t = d_j−d_i → 最小二乘解出 t（tool0 系偏移）
```

### 现场步骤

```bash
python3 scripts/tcp_calib.py            # 默认 8 次采样
```

1. 机器人上电、松刹车、无程序运行（手放急停）
2. 用示教器点动，把**工具尖端**（夹爪上一个尖点）对准桌面固定尖点
3. 回车记录 → **换姿态**（位置不动、旋转 60~90°）再对准 → 回车
4. 采样 ≥6 个、姿态差异大（脚本会提示姿态变化小）
5. 脚本输出 `t = [x, y, z]` 和残差检查（固定点在 base 系应一致，>5mm 说明不准）

### 结果怎么用

- 填到示教器：**安装 → TCP → 输入 X/Y/Z（米）**
- 或写入代码：**抓取点位是 tool0 系的，标定出的 t 要先从点位里扣除**

> ⚠️ 注意：现在 `poses.json` 的点位是"TCP=tool0"下标出来的；
> 标定 TCP 后，要么重新标点位，要么在程序里做偏移。

## 4. 力传感器 → 工具坐标系变换（⚠️ 待办，依赖 ATI 恢复）

- 目标：把 ATI 传感器系的力/力矩转到 robot tool0 系，用于"力控插装/碰撞检测"
- 方法（不需要真值标定板）：
  1. 把机械臂转到**已知姿态**（如 tool0 竖直向下）
  2. 读传感器力：重力在传感器系的方向
  3. 对比 tool0 系预期重力方向 → 求出传感器→tool0 的旋转
  4. 平移（力臂）用第 1 节的 43mm 或按安装尺寸
- 验证：转几个姿态，看转换后的重力矢量始终竖直

## 5. 运动学参数（❌ 手改放弃，结论：标称已足够）

### 实测对比（同姿态，真机 TCP 作为真值）

| URDF | 位置偏差 | 姿态偏差 | 结论 |
|---|---|---|---|
| **标称**（xacro 默认） | **2.6 mm** | 0.0035 rad | ✅ 抓取够用 |
| +delta_theta（正号，正确旋转数学） | 28.3 mm | 0.0159 rad | ❌ 更差 |
| +delta_theta（反号） | 26.0 mm | 0.0189 rad | ❌ 更差 |

### 为什么手改失败（诚实记录）

- `calibration.conf` 的 `delta_theta/delta_a/delta_d` 是**控制器线性化内部模型**的修正量，
  不是直接可套进 URDF 的偏移；`delta_d` 的 J2/J3/J4 值（1.44/-8.66/7.22）是变换后的绝对量
- URDF 的 rpy 是固定轴约定，关节角偏移需**后乘 Rz(δ)**（我做对了这一点，但仍失败）
- 两条路（正/反号）都失败 → 不是符号问题，是**模型约定不同**

### 正确做法（若未来需要亚毫米 FK）

用官方 **`ur_calibration`** 包（`ros-humble-ur-calibration` 在 apt 里），
它按 UR 官方算法把标定导出成驱动可用的参数——不要手改。

### 当前结论

**维持标称 URDF**（2.6mm 对视觉引导抓取足够，夹爪/标记容差通常更大）。
`check_fk.py` 已内置这个验证，以后改任何 URDF 前先跑它。
