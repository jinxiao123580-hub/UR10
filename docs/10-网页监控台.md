# 10 · 网页监控台

监控台只显示数据，不下发机器人或夹爪运动。当前启动脚本只启动 ATI 原始力、相机（可选）和
网页桥；**不会启动未验证的重力补偿进程**。

```bash
cd ~/UR10
bash scripts/start_dashboard.sh --no-browser
```

浏览器访问 <http://127.0.0.1:8080/>。停止时：

```bash
cd ~/UR10
bash scripts/start_dashboard.sh --stop
```

⚠️ **必须在 `~/UR10` 目录下执行**：脚本用的是相对路径，在 `~` 下敲会报
`bash: scripts/start_dashboard.sh: No such file or directory`。

2026-09-18 修复后的行为（修复前"打不开"的三个成因见
[`../experiments/2026-09-18-入口可用性审计.md`](../experiments/2026-09-18-入口可用性审计.md) §3.1）：

- **启动自检**：起来后 `curl` 探活 `http://127.0.0.1:8080/`，应答才打印地址；
  不应答就打印端口占用与桥日志尾部并以退出码 1 结束（不再打印一个打不开的地址）。
- **僵死实例自愈**：若发现有桥进程但端口不应答（历史遗留残留），先清理再启动。
- **`--stop` 真的会停**：SIGTERM → 最多 3 s → SIGKILL，并校验 `8080/9090` 已释放才报成功，
  否则列出仍存活的进程与占用情况并返回退出码 1。
- **重复启动安全**：已在运行且应答正常时，脚本说明"本次没有新起进程"后退出，不影响在跑的实例。
- 清理进程时脚本会排除自身进程链，不会误杀"命令行里恰好含 `ros_web_bridge.py`"的调用者。

启动后，力图仅可解释为 `/ft_sensor/wrench_raw` 的原始数据；不把它用于碰撞停止、力控或
抓取判定。ATI 是单消费者，如果无数据，先结束其它 ATI 采集进程。

相机页面可能显示 bgr8 格式，但本机实测三个通道相同，实际为单色。相机采集与点云有效性仍以
[`09-MechEye相机接入清单.md`](09-MechEye相机接入清单.md) 的保存结果为准；
2026-09-18 相机服务调用无响应的待定性问题见 `docs/00` 与上述审计记录 §3.2。
