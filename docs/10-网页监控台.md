# 10 · 网页监控台（ROS 数据可视化）

一个网页，左边看**相机画面**，右边看**六轴力折线图**，数据全部来自 ROS 话题。

```
   ┌──────────────────────────── 浏览器 ────────────────────────────┐
   │  UR10 视觉 · 力觉 监控台        [已连接] [相机在线]              │
   │ ┌───────────────────────────┐ ┌──────────────────────────────┐ │
   │ │ 📷 Mech-Eye 相机           │ │ ⚖️ ATI 六维力 / 力矩          │ │
   │ │ ┌──────────┐ ┌──────────┐ │ │ ┌────┬────┬────┬────┬────┬──┐│ │
   │ │ │ 彩色画面  │ │ 深度伪彩 │ │ │ │ Fx │ Fy │ Fz │ Tx │Ty │Tz││ │
   │ │ └──────────┘ └──────────┘ │ │ └────┴────┴────┴────┴────┴──┘│ │
   │ │ 点云: 4800 点 中心(...)    │ │  ╱╲   六路实时折线（12s 窗口）│ │
   │ └───────────────────────────┘ └──────────────────────────────┘ │
   └────────────────────────────────────────────────────────────────┘
              ▲ WebSocket (JSON)                    ▲ 图像 base64 JPEG
              │                                      │
   ┌──────────┴──────────────────────────────────────┴──────────┐
   │  scripts/ros_web_bridge.py   （rclpy 订阅 → WebSocket :9090）│
   │  scripts/web_dashboard/      （静态页，HTTP :8080）          │
   └──────────┬──────────────────────────────────────┬──────────┘
              │ ROS 2 话题                            │ ROS 2 服务
   /ft_sensor/wrench            /mechmind/color_image · depth_map · point_cloud
   ATI Net F/T                  Mech-Eye 3D 相机
```

## 1. 一键启动

```bash
bash scripts/start_dashboard.sh
```

它会在**同一个 shell 环境**里起：力传感器节点 → 相机节点（若 SDK 已装）→ 桥 + 网页服务 → 打开浏览器。

```bash
bash scripts/start_dashboard.sh --no-browser   # 不自动开浏览器
bash scripts/start_dashboard.sh --no-camera    # 不起相机
bash scripts/start_dashboard.sh --stop         # 全停
```

打开 <http://127.0.0.1:8080/> 即可。

**前置**：`python3 -m pip install --user websockets`（本项目已装 16.1.1）。

## 2. 实测结果

全部为真机/真数据的验证记录：

| 通道 | 话题 | 实测结果 |
|---|---|---|
| 六维力 | `/ft_sensor/wrench` | **200 Hz** 稳定（14 秒收 2796 帧），6 路波形实时刷新 |
| 彩色画面 | `/mechmind/color_image` | 640×480 **JPEG 11 KB**（服务端把 bgr8 编码成 JPEG 再传，省带宽） |
| 深度图 | `/mechmind/depth_map` | 32FC1 → **伪彩色 JPEG 6.5 KB**，自动按 2%~98% 分位归一化 |
| 点云 | `/mechmind/point_cloud` | 统计量：点数 4800、均值中心 `(-0.007, 0.005, 1.180)` m |

> 图像走 base64 JPEG 而不是原始 `sensor_msgs/Image`：原始 640×480 bgr8 = **921 KB/帧**，
> 200Hz 下用 WebSocket 直传必然卡死；转 JPEG 后 ~11 KB，小了 **80 倍**。

## 3. 桥的协议（自己实现的轻量 rosbridge）

没用 `rosbridge_suite`（要 sudo 装），自写了一个 40 行的 JSON 协议，
用 `websockets` + `rclpy` 实现，**rclpy 在后台线程转，asyncio 在主线跑 WS**。

**浏览器 → 桥**：

```json
{"op":"subscribe","topic":"/ft_sensor/wrench","kind":"wrench"}
{"op":"subscribe","topic":"/mechmind/color_image","kind":"image"}
{"op":"subscribe","topic":"/mechmind/depth_map","kind":"depth"}
{"op":"subscribe","topic":"/mechmind/point_cloud","kind":"pcl_stats"}
{"op":"unsubscribe","topic":"/..."}
{"op":"call_service","service":"/capture_color_image","kind":"mecheye_capture","request_id":1}
{"op":"call_service","service":"/ft_sensor/tare","kind":"trigger","request_id":2}
{"op":"ping"}
```

`kind` 取值：`wrench` / `image` / `depth` / `pcl_stats`。
服务调用 `kind`：`trigger`（std_srvs/Trigger）/ `mecheye_capture`（梅卡曼德的采集服务）。

**桥 → 浏览器**：

```json
{"topic":"/ft_sensor/wrench","data":{"fx":3.9,"fy":5.6,"fz":62.9,"tx":2.26,"ty":2.36,"tz":0.26,"sec":...,"nsec":...}}
{"topic":"/mechmind/color_image","data":{"format":"jpeg","width":640,"height":480,"data":"<base64>"}}
{"topic":"/mechmind/depth_map","data":{"format":"jpeg","width":640,"height":480,"data":"<base64>","min":0.55,"max":1.2}}
{"topic":"/mechmind/point_cloud","data":{"count":4800,"sampled":4800,"px":-0.007,"py":0.005,"pz":1.18,"has_data":true}}
{"op":"call_service","ok":true,"service":"...","response":{...},"request_id":1}
```

## 4. 页面功能

| 功能 | 说明 |
|---|---|
| 六路折线 | Fx Fy Fz Tx Ty Tz，12 秒滚动窗口，15Hz 刷新（数据 200Hz，渲染降频避免卡顿） |
| 当前值大字 | 六路数值实时显示，力 N / 力矩 N·m |
| 去皮按钮 | 调 `/ft_sensor/tare` 服务（软件去皮，不改传感器） |
| 自动刷新 | 工业相机是**服务触发式**，页面每 1.5s 自动调一次采集服务 |
| 手动采集 | "采集一次"按钮 |
| 点云统计 | 点数 + 中心坐标（网页不做真 3D，够定位用） |
| 离线提示 | 相机没接/没装 SDK 时显示"相机离线 · 等待 Mech-Eye SDK"，**力数据照常工作** |
| DEMO 标注 | 2 秒收不到真实力数据时切演示波形，右上角显示 **DEMO 数据** 角标，真数据一到立刻退出 |

## 5. 没有相机也能验证页面

装 SDK 之前，用**模拟相机**（发布同名同格式话题）先把整条画面链路跑通：

```bash
# 终端 1
python3 scripts/fake_mecheye_publisher.py --hz 2
# 终端 2
source /opt/ros/humble/setup.bash && python3 scripts/ros_web_bridge.py
# 浏览器打开 http://127.0.0.1:8080/
```

画面上会画着 **"FAKE CAMERA"** 字样，别当真相机数据。
模拟器同样发布深度图（背景 1.2m / 目标块 0.55m）和点云，用来验证伪彩色与统计链路。

## 6. 故障排查

| 症状 | 原因 | 解决 |
|---|---|---|
| 页面显示"已断开" | 桥没起 / 端口被占 | `bash scripts/start_dashboard.sh`；`ss -tln \| grep 9090` |
| 力数据一直 DEMO | `/ft_sensor/wrench` 没数据 | 起力节点；**确认只有一份力节点在跑**（见下） |
| 力数据时断时续 | **两个进程抢 ATI 的 RDT 流** | 只留一个消费者（RDT 是单目的地单播） |
| 相机一直离线 | 没装 Mech-Eye SDK | 见 [`docs/09`](09-MechEye相机接入清单.md) |
| 画面有但花/卡 | 分辨率过大 + 太多订阅者 | 降 `--hz`、减小分辨率；JPEG 质量在桥里可调 |
| 相机话题订阅了但没图 | 工业相机**不调服务就没图** | 勾选"自动刷新"或点"采集一次" |

> ⚠️ **ATI RDT 是单目的地单播**：它只把数据推给"最后一个发 start 的客户端"。
> 同时跑两个力节点（或一边跑节点一边用 `--check`）会互相抢流，表现为**数据 5 秒一跳**。
> 本项目的力节点已内置自愈（超时自动重申请），但正确做法仍是**只保留一个消费者**。

## 7. 已知限制 / 可扩展

| 限制 | 说明 |
|---|---|
| 点云只给统计 | 网页不做真 3D 渲染；要看点云用 `rviz2` 订阅 `/mechmind/point_cloud` |
| 无 TF 可视化 | 相机与机器人坐标的变换靠 `docs/08` 的手眼标定，网页不参与 |
| 无法远程访问 | 桥监听 `0.0.0.0`，同网段可直接用 `http://<电脑IP>:8080/` 打开；跨网段需自行加认证 |
| 未做随时录像 | 需要回放可加 `ros2 bag record` |

可扩展方向：加"抓取点标定"按钮（把当前点位写进 `poses.json`）、加机器人关节角显示、
把折线数据同时存 CSV、用 ECharts 的 `dataZoom` 做历史回看。
