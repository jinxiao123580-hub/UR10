# 03 · 机械臂控制（走 ROS → 30002）

## 1. 最核心的坑：`def` 光定义不调用，机器人不动

30002 端口是 UR 的 **Secondary Client**，你把一段 URScript 文本发过去，URControl 会执行它。
但 UR 有个硬要求：**脚本要用 `def 名字(): ... end` 包裹**（否则被静默丢弃）。
而包成 `def` 之后——**它只是定义了一个函数，不会自动运行！**

```python
# ❌ 错的：只定义，不调用 —— 机器人纹丝不动，也不报错
"def ros_move():\n  movel(p[...], a=0.3, v=0.05)\nend"

# ✅ 对的：定义 + 显式调用
"def ros_move():\n  movel(p[...], a=0.3, v=0.05)\nend\nros_move()"
```

这个坑极其隐蔽：**没有任何报错**，程序"成功发送"，机器人不动。
排查时你会怀疑网络、怀疑上电、怀疑安全状态，唯独想不到是少了个括号。

`scripts/ur_arm.py` 的 `send_script(script, call=True)` 会自动补上调用，用它就绕开了这个坑。

## 2. 读当前位姿：30001 状态流

UR 的 30001（Primary Client）会以 10Hz 推二进制数据包。包结构：

```
外层包: [4字节长度][1字节包类型=16][若干子包]
子包:   [4字节长度][1字节子包类型][数据]
  子包类型 4 = Cartesian Info（TCP 位姿）
     数据: 6 个 double (大端) = x, y, z, rx, ry, rz（基座坐标系，单位 米/弧度）
  子包类型 1 = Robot Mode
  子包类型 3 = Joint Data（关节角）
  子包类型 0 = Joint Data（另一些固件版本）
  ...
```

`scripts/ur_arm.py::read_packet()` 实现了这个解析，无需 ROS 依赖，纯 stdlib。

> **为什么不用 `get_actual_tcp_pose()`？** 这台机器人的客户端接口**禁止内省函数**
> （`get_actual_*` 会被拒绝）。所以做法是：**电脑从 30001 读出当前位姿 → 在电脑上算目标 →
> 把目标位姿作为字面量写进 URScript 的 `movel(p[...])`**。

## 3. `ur_arm.py` —— 机械臂控制模块

既能当命令行工具，也能 `import` 当库用。

### 命令行

```bash
source /opt/ros/humble/setup.bash && source ~/ros2_ws/install/setup.bash

python3 scripts/ur_arm.py check                # 只读当前 TCP 位姿
python3 scripts/ur_arm.py nudge 0 0 -0.003     # 相对微动 3mm（向下）
python3 scripts/ur_arm.py nudge 0.05 0 0       # 沿 X 前进 5cm
```

`nudge` 会打印"动没动 + 位移多少"，是**验证通路是否活**的最快方式：

```
当前: [0.5778 -0.2628 0.3477]
目标: [0.5778 -0.2628 0.3447]  (偏移 [0.0, 0.0, -0.003])
移动后: [0.5778 -0.2628 0.3446]  位移 0.0031m ✔ 动了
```

### 当库用

```python
from ur_arm import Arm

arm = Arm()                       # 默认 192.168.1.3，可用环境变量 UR_IP 覆盖
print(arm.get_tcp_pose())         # 读当前位姿

arm.movel([0.647, -0.268, 0.276, 1.935, -2.365, 0.0], a=0.3, v=0.05)  # 直线移动（阻塞到走完）
arm.movej([0, -1.5708, 0, -1.5708, 0, 0], a=1.0, v=0.5)               # 关节移动
arm.stop_program()                # 经 dashboard 停
```

| 方法 | 说明 |
|---|---|
| `movel(pose, a=0.3, v=0.05, wait=True)` | 直线移动到绝对位姿；`wait=True` 会轮询 30001 直到真的到位（容差 1mm / 0.02rad） |
| `movej(joints, a, v)` | 关节空间移动（适合长距离、避免奇异） |
| `send_script(text, call=True)` | 发任意 URScript，`call=True` 自动补函数调用 |
| `get_tcp_pose()` | 读 30001 拿当前 TCP 位姿 |
| `stop_program()` | dashboard `stop` |

`movel` 的 `wait` 很关键：URScript 的 `movel` 本身阻塞到走完，但脚本是**异步**发过去的，
`wait=True` 用位姿轮询确认到位，抓放时才不会"还没到就闭爪"。

## 4. 位姿标定：`ur_capture_pose.py`

抓取点/放置点靠手工标定：把机械臂移到位置，然后记录。

```bash
# 手推机械臂（示教器：按住"自由驱动"）或用示教器点动到抓取点
python3 scripts/ur_capture_pose.py pick

# 移到放置点
python3 scripts/ur_capture_pose.py place
```

生成 `~/ur_learn/poses.json`：

```json
{
  "pick":  [0.6474272729282422, -0.268465964721239, 0.2760558063781259,
            1.9351373451718241, -2.3646005215619694, -0.00022114968079682207],
  "place": [0.672239834897491,  0.03678128214703258, 0.2761125259113394,
            1.9351901513169982, -2.3646862311110817, -2.300586535676707e-05]
}
```

前三个是位置 x,y,z（米），后三个是姿态 rx,ry,rz（弧度，轴角表示）。
**抓取点和放置点的 z 应相同**（同一桌面），姿态也应一致（夹爪垂直向下抓）。

> 标定时注意：z 取的是**夹爪指尖刚好接触物体**的高度，脚本会自动在上方 50mm 处插入一个安全高度点。

## 6. 安全与故障

| 现象 | 原因 | 解决 |
|---|---|---|
| 发了脚本没反应 | **没调用函数** / 机器人未上电 / 保护性停止 / 本地模式 | 用 `nudge` 验证；查 `robotmode`、`safetystatus` |
| `movel` 报不可达 | 目标点超出工作空间或路径不可直线到达 | 改用 `movej` 先接近，再 `movel` 走最后一段 |
| 走到一半停住 | 奇异点 / 碰撞检测 / 关节限位 | 换姿态（调整 rx,ry,rz），或提高安全高度 |
| 位姿读出来全是 0 | 30001 流没解析到 type=4 子包 | 确认机器人 RUNNING；重连读 |
| 想立刻停 | — | `ros2 service call /ur_link/dashboard/stop std_srvs/srv/Trigger` 或急停 |

## 7. 125Hz 实时状态读取

2026-09-11 已验证 CB3 的 30003 和 30013 均输出固定 1220B 状态帧，频率
约 125Hz。使用 `scripts/probe_ur_realtime.py` 做持续收包检查。

1220B 帧以 4 字节大端包长开头。当前固件实测字段偏移（从含包长的整帧
起点计算）为：

- `q_actual`：偏移 252，6 个大端 float64。
- `tool_vector_actual`：偏移 444，6 个大端 float64。
- `tcp_speed_actual`：偏移 492，6 个大端 float64。

静止现场交叉验证：30003 TCP 为
`[0.647636,-0.210642,0.513494,1.934716,-2.364199,0.002129]`，同一时刻
30001 TCP 最大分量差 `3.23e-5`，TCP 速度六轴全零。因此这些偏移已由
本机数据验证，不是照搬其他固件表格。

实时状态读取已经通过。`servoj` 的单关节小幅测试结果见下一节；完整恒力
控制安全状态机仍未实现，不得直接把状态流与 ATI 数据裸接成闭环。

## 8. servoj 小幅真机验收（2026-09-11）

`scripts/test_servoj.py` 在腕 3 关节执行 1 个周期的正弦目标：幅度
`±0.005 rad`、周期 2s、控制周期 8ms、`lookahead_time=0.1`、`gain=100`。
30003 同步测得：

- 502 帧，125.01Hz。
- 实际关节往返范围 0.010029rad，命令总范围为 0.010rad。
- 最大速度 0.020095rad/s。
- 相邻 125Hz 状态帧最大关节步进 0.000179rad。
- 控制器接受脚本，响应连续，无超幅、保护停止或状态流中断。

这证明当前 CB3 接受 `servoj` 且能产生受限平滑响应，但只完成了单关节小幅
验收。恒力控制仍必须增加通信看门狗、力/速度/位移限幅和停止状态机。
