# 04 · 夹爪控制（电脑直连 63352）—— 本项目最有价值的部分

这一节是整个项目卡了最久、最后被彻底解决的地方。**结论先行：夹爪不需要示教器、不需要 URCap 编程、
不需要 socket 转发，电脑直接连机器人上的 `63352` 端口就能开合。**

---

## 1. 先搞清 Robotiq 夹爪的驱动架构

Robotiq 的 UR URCap（本机版本 `1.8.13.22852`）**不是**让你的程序直接跟夹爪硬件说话。
它的结构是：

```
  你的 URScript 程序
        │  rq_set_pos(255) / rq_activate() / rq_get_position()
        ▼
  URCap 生成的 URScript 函数库（76KB，装在程序开头）
        │  TCP socket → 127.0.0.1:63352   ← 关键！
        ▼
  drivergripper  ← 机器人上的守护进程（由 URCap 启动）
        │  RS-485（工具端）
        ▼
  Robotiq 2F-85 夹爪本体
```

在生成的 `*.script` 里能看到这两行"铁证"：

```urscript
rq_gripper_socket_ip_address = "127.0.0.1"
rq_gripper_socket_port = 63352
```

而守护进程确实在跑（机器人 SSH 里查）：

```bash
$ netstat -tlnp | grep 63352
tcp6  0  0  :::63352  :::*  LISTEN  3063/drivergripper
$ ps aux | grep -i robotiq
root  3036  runsv bundle@com.robotiq.urcap.gripper@-96457847
root  3038  /bin/bash /root/GUI/felix-cache/bundle1489/data/com/robotiq/urcap/gripper/impl/daemon/robotiq_2f_gripper_driver.sh
root  3063  ./drivergripper
```

### 🎯 为什么电脑能直连？

因为守护进程监听的是 **`:::63352`——IPv6 通配地址**，也就是**监听所有网卡**，
而不是只绑 `127.0.0.1`。所以在电脑上直接 `connect("192.168.1.3", 63352)` 就通。

验证（电脑上跑）：

```bash
python3 - <<'EOF'
import socket
s = socket.create_connection(("192.168.1.3", 63352), timeout=3)
s.sendall(b"GET SID\n"); print(s.recv(100))   # → b'SID [9]\n'   夹爪已连接
s.sendall(b"GET POS\n"); print(s.recv(100))   # → b'POS 3\n'     位置 3/255(全开)
EOF
```

**能连上并回答，就意味着夹爪本体是活的、通信链路是全通的。**

## 2. 致命陷阱：`rq_activate()` 会死锁

这是"示教器 socket 方案"失败的**真正原因**。看 URCap 生成的 `rq_activate()` 实现：

```urscript
def rq_activate(gripper_socket="1"):
    if (not rq_is_gripper_activated(gripper_socket)):
        rq_reset(gripper_socket)
        while(not rq_get_var("ACT", 1, gripper_socket) == 0 or not rq_get_var("STA", 1, gripper_socket) == 0):
            rq_reset(gripper_socket)
            sleep(0.008)
        end
        rq_set_var("ACT",1, gripper_socket)
    end
end
```

那个 `while` 的条件是 **"等 ACT 变成 0 且 STA 变成 0"**。
而夹爪**正常工作时就是 `ACT=1`**（已激活）！于是：

- `not (ACT == 0)` → `not False` → `True` → **循环继续**
- 永远等不到 `ACT=0`（除非 reset 真的生效）→ **死循环，程序卡死在这里**

### 现象（完美对应之前的困惑）

| 现象 | 解释 |
|---|---|
| 服务器 30010 **能看到机器人连入** | `socket_open()` 在第 1 行，执行成功了 |
| 之后**发什么命令都没回执** | 卡在第 2 行 `rq_activate()` 的 while 里，永远走不到读命令的循环 |
| 连接**一直不断开** | 程序没退出，也没报错，就是**卡住** |
| 示教器看着像"在播放" | 程序确实在 PLAYING，只是陷在死循环 |

**结论：不要调 `rq_activate()`。** 夹爪平时就是 `ACT=1`，本来就激活好了。
（`ACT=0` 只发生在断电重启后或故障复位后；真需要时用下面的 `SET ACT 1` 直接发。）

## 3. Robotiq ASCII 协议速查

守护进程说的是标准 **Robotiq ASCII 协议**（命令以 `\n` 结尾，响应一行文本）。
以下命令全部**实测可用**：

> 📌 **回复格式是补零 / 带括号的**，解析时注意（实测原始响应）：
> ```
> GET SID  ->  SID [9]      ← 带方括号
> GET ACT  ->  ACT 1
> GET FLT  ->  FLT 00       ← 补零
> GET PRE  ->  PRE 000      ← 补零
> ```
> 所以别直接 `int(parts[1])`，要用正则抠数字（`scripts/rq_gripper.py::query()` 已处理）。

### 读（GET）

| 命令 | 响应示例 | 含义 |
|---|---|---|
| `GET SID` | `SID [9]` | 夹爪 ID 列表；非空=夹爪已连接（9 是默认 SID） |
| `GET POS` | `POS 3` | **当前开口位置** 0=全开，255=全闭 |
| `GET PRE` | `PRE 0` | 目标位置（请求值） |
| `GET OBJ` | `OBJ 2` | **物体检测**：见下表 |
| `GET STA` | `STA 3` | 状态：0=复位中 1=激活中 2=激活完成 3=激活完成+就绪 |
| `GET FLT` | `FLT 0` | 故障码，0=无故障 |
| `GET ACT` | `ACT 1` | 1=已激活 |
| `GET GTO` | `GTO 1` | 1=正在执行动作 |
| `GET SPE` / `GET FOR` | `SPE 255` | 速度 / 力度 |

### 写（SET）

| 命令 | 作用 |
|---|---|
| `SET POS 255` | 目标位置：`0`=全开，`255`=全闭 |
| `SET SPE 255` | 速度 0-255 |
| `SET FOR 255` | 力度 0-255 |
| `SET GTO 1` | **"执行"开关**——设完 POS/SPE/FOR 后必须发这个，夹爪才会动 |
| `SET ACT 1` | 激活夹爪（断电重启后才需要） |
| `SET ATR 0` / `SET ARD 0` | 自动释放（开/闭方向），一般不设 |

### OBJ 物体检测码（判断"有没有夹到东西"）

| 值 | 含义 |
|---|---|
| `0` | 正在运动中 |
| `1` | 张开时检测到物体 |
| **`2`** | **闭合时检测到物体 → 夹住了！** |
| `3` | 到达目标位置但**没检测到物体 → 抓空了** |

**这是抓放成功与否的唯一客观依据**，比"看着像夹住了"可靠得多。

### 正确的开合序列

```
SET SPE 255      # 速度
SET FOR 255      # 力度
SET POS 255      # 目标：闭合（0 是张开）
SET GTO 1        # ← 别忘了这句，否则不动
GET POS          # 轮询到位置（约 1~2 秒走完）
GET OBJ          # 2 = 夹住了
```

## 4. `rq_gripper.py` —— 夹爪控制模块

### 命令行

```bash
python3 scripts/rq_gripper.py status     # 读状态
python3 scripts/rq_gripper.py open       # 张开
python3 scripts/rq_gripper.py close      # 闭合
python3 scripts/rq_gripper.py test       # 开合自检（建议第一次先跑这个）
```

`python3 scripts/rq_gripper.py test` 实测输出：

```
① 初始: SID=None ACT=1 GTO=0 STA=3 FLT=0 POS=3 PRE=0 OBJ=0
② 激活: OK | ...
③ 闭合 -> POS 230
    ACT=1 GTO=1 STA=3 FLT=0 POS=230 PRE=255 OBJ=3
④ 张开 -> POS 3
    ACT=1 GTO=1 STA=3 FLT=0 POS=3 PRE=0 OBJ=0
✔ 自检完成（夹爪如果实际开合过，就说明电脑直控成功）
```

> `SID=None` 是解析小瑕疵（守护进程回的是 `SID [9]`，带方括号），不影响其它字段。

### 当库用

```python
from rq_gripper import RobotiqGripper

g = RobotiqGripper()            # 默认 192.168.1.3:63352
g.connect()
print(g.status())               # {'SID':.., 'ACT':1, 'STA':3, 'POS':3, ...}
g.close()                       # 闭合，等到位（返回最终 POS）
print(g.object_detected())      # 2 = 夹住了
g.open()                        # 张开
g.close_socket()

# 也可以精确控制位置/速度/力
g.move(128, speed=200, force=100)
```

| 方法 | 说明 |
|---|---|
| `connect()` / `close_socket()` | 连接/断开（支持 `with` 语法） |
| `status()` | 一次读全部字段，返回 dict |
| `activate(wait=5.0)` | 确保激活（已激活则立即返回 True，**不会死锁**） |
| `move(pos, speed=255, force=255)` | 到指定位置，等到位后返回实际 POS |
| `open()` / `close()` | 张开 / 闭合（等价 `move(0)` / `move(255)`） |
| `query("POS")` | 发 `GET POS` 并返回值 |
| `set_var("POS", 255)` | 发 `SET POS 255` |
| `object_detected()` | 读 OBJ |

## 5. 为什么放弃"示教器 socket 方案"

在发现 63352 之前，试过让示教器跑一个程序、电脑起服务器监听 30010、示教器 `socket_open` 连过来读命令。
这条路**最终放弃**，原因：

1. **`rq_activate()` 死锁**（见上文），一加就卡死；
2. **URCap 会往程序里塞 76KB 代码**（安装节点生成的 `def rq_*` 函数库、真空检测线程等），
   手粘脚本时极易把残留代码一起带进去；
3. **示教器的 Script 节点是 `type="File"` 且带 `cachedContents` 缓存** ——
   你改了 `/programs/xxx.script`，程序跑的却还是 `.urp` 里那份**过期缓存**；
4. **每次改代码都要重播程序**，socket 只能 open 一次，迭代极慢；
5. 多一层不稳定的中间人，故障点翻倍。

而直连 63352 方案：**不需要示教器做任何事，改代码不用重播，迭代以秒计。**
旧方案留档在 `legacy/`，仅供对照。

## 6. 夹爪常见故障

| 症状 | 原因 | 解决 |
|---|---|---|
| 连不上 63352 | 守护进程没起（机器人刚开机/URCap 崩了） | SSH 进机器人查 `ps aux \| grep drivergripper`；`runsv` 会自动重启，等几秒；实在不行示教器里加载一次带夹爪 URCap 的程序 |
| `FLT` 非 0 | 夹爪故障（过载/通信错） | 发 `SET ACT 0` 再 `SET ACT 1` 复位；示教器 URCap 面板里点"复位" |
| 发 `SET POS` 不动 | 忘了 `SET GTO 1`；或未激活 | 补 `SET GTO 1`；查 `ACT` 是否 1 |
| `POS` 停在中间（如 104/230）不到 255 | **正常**——手指被物体挡住了 | 这正是"夹住东西"的表现，配合 `OBJ=2` 确认 |
| `OBJ=3` 且 `POS≈255` | 抓空了（物体不在位） | 检查物体位置/抓取点标定 |
| 夹爪开合但方向反了 | POS 含义记反 | `0`=张开，`255`=闭合 |
| 力度太大夹坏物体 | `FOR` 给太满 | `SET FOR 100~150` 降低力度 |
