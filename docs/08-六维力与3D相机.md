## Mech-Eye PRO XS

- 设备：`192.168.1.33`，型号 `Mech-Eye PRO XS`，SN `RAM35238A3020004`，SDK `2.5.0`。
- SDK、ROS 接口、2D 图、深度图、普通点云和纹理点云均已完成触发验收。
- **2D 图像只能是单色，这是硬件规格，不是配置错误**：PRO XS 的 2D 传感器为 Monochrome，
  官方规格表标注 `2D image color: Monochrome`，且型号表中 PRO XS 没有任何彩色物料号
  （`C` 后缀）版本。GVCP 型号证据见 `outputs/camera/model-identification-20260918.json`。
- 灰色三通道的来历：SDK 的 `Frame2D::getColorImage()` 在 `colorType()` 为 Monochrome 时，
  按 `Blue = Gray, Green = Gray, Red = Gray` 把灰度复制成三通道；而官方 ROS 2 接口
  `capture_color_image_callback` 无条件调用它，并以 `BGR8` 发布 `/mechmind/color_image`。
  所以 bgr8 三通道逐像素相同，纹理点云 `rgb` 字段也相同。话题名中的 `color` 是命名遗留
  （SDK 2.0.2 的 `CaptureColorMap` 在 2.3.4 改名为 `CaptureColorImage`，话题名未改），
  不代表数据是彩色。
- 因此：不得把 `/mechmind/color_image` 当作彩色识别依据，也不需要再为“恢复彩色”排查参数或
  链路；需要真彩色只能更换彩色型号（PRO S / PRO M / NANO 的 `C` 后缀版本，PRO XS 无彩色
  版本）或外挂 RGB 相机。单色对棋盘格、角点、边缘检测和点云质量反而更有利。
- 有效点云、图像和元数据的采集验收：

```bash
cd ~/UR10
source /opt/ros/humble/setup.bash
source ~/colcon_ws/install/setup.bash
python3 scripts/validate_mecheye_capture.py
```

## 坐标与手眼

当前使用 eye-in-hand：相机随末端运动，棋盘格固定。相机于2026-10-27重新安装，旧安装的外参不适用于当前安装；新参数为
[`config/handeye_eye_in_hand_20261027.yaml`](../config/handeye_eye_in_hand_20261027.yaml)，方向为`tool0_from_camera`。本次机器人位姿来自控制器静止状态回读，采样前后核对当前TCP偏移为零。

新方法将图像棋盘角点射线与组织点云中的棋盘平面相交，再以3D刚体拟合得到棋盘位姿，最后进行Park手眼求解，并以Horaud交叉核对。15组训练样本先固定；原5组留出在PnP方案平移门禁失败后用于算法诊断，另采5组全新姿态验收改进版，未重新拟合候选外参。

- 全新5组独立样本：固定棋盘闭环平移RMS **0.3523 mm**、最大 **0.4041 mm**；旋转RMS **0.06424°**、最大 **0.09471°**。
- 相机光轴与`tool0 +Z`夹角约 **0.7521°**。相机原点在tool0中为`[0.04707494, 0.15015738, 0.16350799] m`；不能据此假定相机X/Y轴与tool0同向，完整旋转见YAML。
- 这些数字表示固定棋盘的跨姿态闭环一致性；未使用独立计量基准验证真机绝对定位精度，棋盘6mm尺度由用户确认沿用，本轮未重新测量打印比例。
