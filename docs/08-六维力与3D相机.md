# 08 · ATI Net F/T 与 Mech-Eye

## ATI Net F/T

- 设备：`192.168.1.2`，RDT UDP `49152`。
- RDT 只会向最后一个请求数据流的消费者发送数据；同一时刻只能运行一个 ATI 节点。
- 已验证的原始 ROS 话题为 `/ft_sensor/wrench_raw`，约 200 Hz，坐标系为 `ft_sensor`。
- 所有现有重力补偿配置均为 `valid: false`，不得用于力控、碰撞停止或抓取判定。

只读检查：

```bash
cd ~/UR10
python3 scripts/ati_netft_node.py --check --hz 10
```

新重力标定只能用原始话题，采集、拟合和独立验证要求见
[`12-力传感器重力补偿.md`](12-力传感器重力补偿.md)。

## Mech-Eye PRO XS

- 设备：`192.168.1.33`，SDK `2.5.0`。
- SDK、ROS 接口、2D 图、深度图、普通点云和纹理点云均已完成触发验收。
- 图像的 bgr8 三个通道逐像素相同，纹理点云 RGB 也相同；当前输出是单色，不可作为彩色识别依据。
- 有效点云、图像和元数据的采集验收：

```bash
cd ~/UR10
python3 scripts/validate_mecheye_capture.py
```

## 坐标与手眼

当前使用 eye-in-hand：相机随末端运动，棋盘格固定。`base→tool0` 使用官方工厂运动学；
手眼参数为 `config/handeye_eye_in_hand_20260917.yaml`。棋盘格逐角点的 PnP—点云几何误差
RMS 为 `0.692 mm`，但真实物块中心定位仍未独立验收。

因此当前只允许视觉候选和安全悬停验证；不得自动下降抓取。任何视觉目标都必须在 `base`
坐标系中表达，不能把 `base_link` 当作控制器基坐标。
