# 05 · 抓放状态与当前替代流程

## 当前结论

旧的完整抓放脚本已禁用：它依赖保留的旧 ROS 桥，且其中的负载质量与重心没有独立测量验证。
当前保留一个独立的**位置式**抓放示例，不使用力传感器或重力补偿：
`scripts/position_pick_place.py`。

它通过控制器原生 `movel` 和 Robotiq ASCII 完成“上方 → 下降 → 闭合 → 抬起 → 放置 → 张开”，
每段运动检查到位，夹爪必须报告 `OBJ=2` 才继续。示例只适合已人工确认的固定点位，不是视觉
自主抓取；当前脚本只完成 dry-run，尚未完成本机真机抓放验收。

课程固定点演示可使用显式 `--demo`，该模式不等待 `OBJ=2`，即使空夹也继续位置流程：

```bash
cd ~/UR10
python3 scripts/position_pick_place.py \
  --poses config/position_pick_place.example.json \
  --height 0.05 --speed 0.02 --acceleration 0.05 \
  --demo
```

这只证明预设位置运动和夹爪开合流程，不证明物体被抓住；不使用 ATI 或任何力控。

反向从终点搬回起点：

```bash
python3 scripts/position_pick_place.py \
  --poses config/position_pick_place.example.json \
  --height 0.05 --speed 0.02 --acceleration 0.05 \
  --demo --swap
```

2026-09-18 已完成一次真机位置搬运闭环，但闭合时 `OBJ=3`，夹持由用户现场确认后才继续；
因此这是“位置运动 + 人工确认夹持”，不是自动抓取验收。数值证据见
[`../experiments/2026-09-18-位置抓放人工确认闭环.md`](../experiments/2026-09-18-位置抓放人工确认闭环.md)。

2026-09-17 已完成一次“视觉候选 + 人工修正”的物块抓起、提升和原位放回。夹爪状态为
`POS=102 / OBJ=2 / FLT=0`，但初始视觉候选与人工确认抓取中心的 XY 偏差为 `35.84 mm`。
这不是全自动视觉抓取的验收通过。

```bash
cd ~/UR10

```

上述均为只读检查。手眼标定参数、独立验收数据和视觉定位的当前限制见
[`../HANDOVER.md`](../HANDOVER.md) 与 [`14-待办与已知问题.md`](14-待办与已知问题.md)。

位置式示例先离线检查：

```bash
cd ~/UR10
python3 scripts/position_pick_place.py \
  --poses config/position_pick_place.example.json --dry-run
```

示例 JSON 点位来自历史示教记录，不代表当前现场仍安全可用。真机运行前必须人工重新确认
两点、抬升高度和周围空间；运行时只做位置控制，不读取 ATI，也不进行力控。

## 恢复自动抓放前的准入条件

1. 在多个重新摆放的已知物体位置，独立测得视觉中心误差并通过门限。
2. 用负载向导或其他独立方法确认夹具和物体的质量、重心；不复用历史估计值。
3. 采用官方驱动/标准轨迹控制器，完成离线、假硬件、单段低速和安全状态监视验收。
4. 每次下降前保留安全悬停和人工急停条件，夹爪闭合后复核 `OBJ` 与提升结果。

原始证据在 `experiments/2026-09-17-视觉抓取闭环.md` 和 `outputs/`。历史代码仅为复盘，
不构成运行说明。
