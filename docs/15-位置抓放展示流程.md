# 15 · 位置抓放展示流程

本流程用于课程展示固定点位置抓放。它使用控制器原生 `movel` 和 Robotiq ASCII，不使用
ATI、重力补偿、视觉定位或力控。

`--demo` 会忽略夹爪 `OBJ` 状态并继续预设位置流程，因此只证明“机械臂到点 + 夹爪开合 +
搬运路径”可以演示，不证明物块被抓住。现场必须有人在急停旁，示例点位必须先确认没有
障碍物。

## 展示前准备

示教器上完成：解除急停、上电、松刹车，确认机器人处于可运行状态。电脑重启后按以下顺序
打开三个终端。

## 终端 1：网络与机器人检查

```bash
cd ~/UR10
ip addr
ping -c 3 192.168.1.3
python3 scripts/diagnose.py
```

必须看到：

```text
ping 192.168.1.3 ... OK
robotmode -> RUNNING
safetystatus -> NORMAL
30002 URScript ... OK
63352 夹爪守护进程 ... OK
```

如果检查失败，停止展示，不要发送运动命令。

## 终端 2：夹爪反馈检查

这一步只开合夹爪，不移动机械臂：

```bash
cd ~/UR10
python3 scripts/verify_gripper_motion.py \
  --duration 2 \
  --interval 0.10
```

本机空夹实测反馈为：

```text
打开：POS=3
闭合过程：POS=3 -> 22 -> 103 -> 191 -> 230，PRE=255
恢复打开：POS=230 -> 217 -> 153 -> 77 -> 8 -> 3
```

记录保存到 `outputs/gripper/motion-verification.json`。

## 终端 3：固定点位置抓放展示

先做一次不连接硬件的参数检查：

```bash
cd ~/UR10
python3 scripts/position_pick_place.py \
  --poses config/position_pick_place.example.json \
  --dry-run
```

确认现场安全后运行演示：

```bash
cd ~/UR10
python3 scripts/position_pick_place.py \
  --poses config/position_pick_place.example.json \
  --height 0.05 \
  --speed 0.02 \
  --acceleration 0.05 \
  --demo
```

流程为：取物点上方 → 下降 → 夹爪闭合 → 抬升 → 放置点上方 → 下降 → 张开 → 抬升离开。
脚本会输出每个步骤和实际 TCP 到位误差。`--demo` 下即使 `OBJ` 不是 `2` 也会继续，所以
展示时必须由现场人员观察物块是否真的被夹住。

## 往返循环展示

要完成“起点 → 终点 → 起点”的往返展示，可一次设置循环次数。`--pingpong` 会让奇数轮
从起点到终点、偶数轮从终点回到起点；例如循环 4 轮：

```bash
cd ~/UR10
python3 scripts/position_pick_place.py \
  --poses config/position_pick_place.example.json \
  --height 0.05 \
  --speed 0.02 \
  --acceleration 0.05 \
  --demo \
  --pingpong \
  --cycles 4
```

`--cycles N` 设置轮数；`--swap` 则表示每一轮固定从终点抓回起点，不能与 `--pingpong`
同时使用。

## 展示结束检查

```bash
cd ~/UR10
python3 scripts/diagnose.py
python3 scripts/check_current_docs.py
```

预期最终状态为 `RUNNING / NORMAL`，夹爪通常为 `POS=3`。若出现保护停、通信中断或异常
姿态，立即停止程序并使用示教器急停；不要重复运行演示命令。

## 当前限制

- 示例 JSON 中的点位来自历史示教，换工作台、物块或夹爪安装后必须重新确认。
- 该流程不是视觉自主抓取，不能作为手眼标定或物体定位验收。
- 该流程不读取 ATI，不进行恒力控制、碰撞停止或抓取成功自动判定。
