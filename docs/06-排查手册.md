# 06 · 当前排查手册

先在机器人不动的条件下运行：

```bash
cd ~/UR10
python3 scripts/diagnose.py
python3 scripts/verify_ur_payload.py
python3 scripts/monitor_ur_safety.py --duration 3
python3 scripts/validate_mecheye_capture.py
```

| 现象 | 当前处理方式 |
|---|---|
| UR 不可达 | 检查电脑 `192.168.1.10/24`、机器人 `192.168.1.3`、网线和示教器状态；代理可能抢占 `192.168.1.0/24` 路由。 |
| 机器人未上电或保护停 | 由现场人员在示教器确认周围安全后上电、松刹车或恢复；不要使用自动恢复脚本。 |
| 官方驱动连不上 | 在干净 ROS 环境启动，见 [`02`](02-官方ROS2驱动.md)；确认 External Control 程序和 Remote Control。 |
| ATI 没数据或反复恢复 | 只保留一个 RDT 消费者；结束其它 ATI 节点后重新启动数据节点。 |
| ATI 数值可见但补偿不可信 | 这是预期限制。只记录 `/ft_sensor/wrench_raw`，不要用于力控或抓取判断。 |
| 相机有图但“颜色”异常 | 本机输出为单色；检查采集元数据，不以话题名称推断真彩色。 |
| 视觉抓取位置偏 | 自主下降尚未授权。先在多个已知物块位置测量物体中心误差，保留安全悬停和人工确认。 |

诊断结论、控制器日志和原始采样必须落到 `outputs/`；失败原因和复现实验写到 `experiments/`。
