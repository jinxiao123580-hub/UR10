# 06 · 排查手册（症状 → 原因 → 解决）

## 0. 先跑一键体检

```bash
python3 scripts/diagnose.py
```

它会依次检查：网络 ping → 关键端口 → 机器人模式/安全状态 → TCP 位姿 → 夹爪状态，并给出结论。
**九成问题在这一步就能定位。**

---

## 1. 速查表

| 症状 | 最可能的原因 | 解决 |
|---|---|---|
| `ping 192.168.1.3` 不通 | 网线/网口错、控制柜没开机、电脑不在同网段 | 见 `docs/01` 网络故障表 |
| ping 通但所有端口连不上 | 电脑代理（sing-box/Clash）劫持路由 | 跑 `scripts/network_setup.sh` 加策略路由 |
| 发了 URScript，机器人**不动也不报错** | ①`def` 没调用 ②未上电/保护性停止/本地模式 | 用 `ur_arm.py nudge 0 0 -0.003` 验证通路；查 `robotmode` |
| 机械臂走到一半停住 | 奇异点、关节限位、碰撞检测 | 调整姿态或改 `movej` 先接近 |
| 示教器程序"在播放"但**不响应命令** | `rq_activate()` 死锁 | 见 `docs/04` 第 2 节，删掉 `rq_activate()` |
| 30010 连上但**没有回执**、连接也不断开 | 同上（程序卡在激活循环里） | 改用直连 63352 方案 |
| 改了 `.script` 文件但跑的**还是旧代码** | `.urp` 里 Script 节点的 `cachedContents` 缓存 | 见 `docs/07`，直接改 `.urp` |
| 示教器脚本里凭空多出**几千行代码** | URCap 安装节点生成的函数库（`def rq_*` 等） | 正常现象，别手删；用直连方案绕开 |
| 夹爪连不上 63352 | `drivergripper` 没起 | SSH 查进程；等 `runsv` 自动重启 |
| 夹爪 `SET POS` 不动 | 忘了 `SET GTO 1`，或未激活 | 补 `GTO`；查 `ACT=1` |
| 夹爪 `POS` 停在 104/230 | **正常**，手指被物体挡住 | 配合 `OBJ=2` 确认夹住 |
| 抓放时 `OBJ=3` 抓空 | 物体不在位 / 抓取点标定偏差 | 重新 `ur_capture_pose.py pick` |
| 电脑突然不能上网 | 配网时给机械臂网口设了默认网关 | `network_setup.sh` 已避免；检查 `ip route` |

## 2. 完整踩坑记录（时间线，含"为什么")

### 坑 1 · 绕了一大圈的示教器 socket 方案

**做法**：示教器跑一个 `socket_open("192.168.1.10", 30010)` + `while True` 读命令的程序，
电脑起服务器下发 `grip`/`release`。

**现象**：服务器能看到机器人连入，但发命令**永远没回执**，连接也不断开。

**真因**（后来才挖出来）：`rq_activate()` 内部的等待循环
`while(not rq_get_var("ACT")==0 or not rq_get_var("STA")==0)` 在夹爪**本来就 `ACT=1`** 时
**永远出不来**。程序卡在第 2 行，走不到读命令的循环。

**教训**：出问题时要**贴日志、贴代码、贴实际文件内容**去定位，
不要把"连上了"当成"通了"。最后是靠 SSH 进机器人把 `.script` 原文捞出来才看清。

### 坑 2 · URCap 往程序里塞 76KB 代码

**现象**：示教器的脚本节点里"自动多出几千行代码"，手动粘贴的内容被淹没。

**真因**：程序的 `.script` 开头是 URCap **安装节点**生成的函数库——
Robotiq 夹爪的 `def rq_activate()`、`def rq_set_pos()`、真空检测线程等，
加上 External Control URCap 的节点代码。这是**正常生成物**，不是 bug。

**教训**：别在示教器里跟这 76KB 较劲。要么用 `docs/07` 的方法直接改 `.urp`，
要么（推荐）**根本不用示教器**——直接连 63352 控制夹爪。

### 坑 3 · Script 节点的 `cachedContents` 过期缓存

**现象**：程序里的脚本明明改了，跑的却是旧逻辑。

**真因**：`.urp` 里 Script 节点是这样的：

```xml
<Script type="File">
  <cachedContents>socket_open(&quot;192.168.1.10&quot;,30010,&quot;g&quot;) ... </cachedContents>
  <file>/programs/jx_test.script</file>
</Script>
```

**程序执行用的是 `cachedContents`（或 file 指向的 `.script`），两者可能不一致**——
你更新了 `.script` 文件，`.urp` 里的缓存还是老的。

**教训**：用 `docs/07` 的方法，把 `.urp` 解压出来看**真实内容**，别猜。

### 坑 4 · 30002 发了 `def` 但不调用（最隐蔽）

**现象**：脚本"发送成功"，机器人**没有任何反应，也不报错**。

**真因**：UR 的 30002 要求脚本 `def` 包裹，但**包裹之后必须显式调用函数**：

```python
"def ros_move():\n  movel(...)\nend"          # ❌ 只是定义，不执行
"def ros_move():\n  movel(...)\nend\nros_move()"  # ✅
```

**教训**：**用 `ur_arm.py nudge` 做通路验证**——
它读前后位姿并打印"位移多少米 ✔动了/✘没动"，把"以为发了"变成"确认动了"。

### 坑 5 · 代理隧道抢路由

**现象**：机械臂时通时断、偶发超时；有时干脆连不上。

**真因**：电脑上用 USB 网卡上网并跑着 sing-box（`singbox_tun` 虚拟网卡）。
去 `192.168.1.0/24` 的流量被代理接管。

**教训**：`scripts/network_setup.sh` 里加策略路由，把机械臂网段**排除在代理之外**：

```bash
ip rule add to 192.168.1.0/24 lookup main pref 100    # 机械臂流量走主表（直连）
```

### 坑 6 · 夹爪其实一直好好的

**现象**：折腾几小时，一直以为"夹爪坏了 / 断电重启后失活"。

**真相**：SSH 进机器人一问守护进程：

```
GET SID → SID [9]     夹爪连接正常
GET POS → POS 3       位置正常
GET ACT → 1           早就激活了
GET FLT → 0           没有故障
```

**夹爪从头到尾都是好的**，坏的只是"我们用错了控制路径"。

**教训**：**先问硬件本体**（直连守护进程/查寄存器），
再怀疑上层脚本。上层有一万种方式骗你，硬件不会。

## 3. 诊断命令备查

```bash
# ── 网络 ──
ping -c 2 192.168.1.3
ip -4 addr show | grep -A1 enp0s31f6
ip route get 192.168.1.3                # 看走哪个网卡（不该出现 singbox_tun）

# ── 端口 ──
for p in 29999 30001 30002 63352; do
  timeout 2 bash -c "cat < /dev/null > /dev/tcp/192.168.1.3/$p" 2>/dev/null \
    && echo "$p 开" || echo "$p 关"
done

# ── 机器人状态 ──
python3 - <<'EOF'
import socket, time
for cmd in ["robotmode", "safetystatus", "programState", "get loaded program"]:
    s = socket.create_connection(("192.168.1.3", 29999), timeout=3); s.recv(4096)
    s.sendall((cmd + "\n").encode()); time.sleep(0.4)
    print(f"{cmd:20s} -> {s.recv(4096).decode().strip()}"); s.close()
EOF

# ── 夹爪 ──
python3 scripts/rq_gripper.py status

# ── 机械臂通路（读前后位姿对比）──
python3 scripts/ur_arm.py nudge 0 0 -0.003

# ── 机器人内部（SSH）──
ssh root@192.168.1.3     # 密码 easybot
#   ps aux | grep -iE 'drivergripper|URControl'
#   netstat -tlnp | grep -E '63352|30002'

# ── ROS 侧 ──
ros2 node list
ros2 topic list
ros2 topic echo /joint_states --once
ros2 service call /ur_link/dashboard/robotmode std_srvs/srv/Trigger
```

## 4. 出问题时的排查顺序（照这个顺序走，别跳）

```
1. diagnose.py 全绿了吗？              → 不绿，先修网络/上电
2. robotmode = RUNNING？               → 不是，示教器上电+松刹车
3. ur_arm.py nudge 动了吗？            → 不动，查 docs/03 的三条硬规则
4. rq_gripper.py test 开合了吗？       → 没开合，查 docs/04 第 6 节
5. 两条都通了，抓放失败？              → 看 OBJ：2=夹住 / 3=抓空 → 重标点位
```

**每一步都要有客观证据**（位姿数值、POS/OBJ 数值、端口状态），
不要靠"看起来在跑"判断。这个项目里所有的坑，本质都是"以为通了实际没通"。
