# ATI 力数据通道（已验证部分）

> 当前**没有通过独立验收的重力补偿参数**。
> `/ft_sensor/wrench_compensated` 不得用于碰撞停止、恒力控制、
> 插装或抓取成功判定。

本文只收录已经真机验证的数据通道和软件边界。失败的标定参数、
样本分析和假设保存在
[`experiments/2026-09-11-重力补偿标定与失败验收.md`](../experiments/2026-09-11-重力补偿标定与失败验收.md)。

## 已验证话题

| 话题 | 含义 | 验证状态 |
|---|---|---|
| `/ft_sensor/wrench_raw` | ATI 物理原始读数，不受进程内 Tare 影响 | 约 200 Hz 稳定发布 |
| `/ft_sensor/wrench` | 兼容话题，已扣除当前进程的软件 Tare | 约 200 Hz 稳定发布 |
| `/ft_sensor/software_bias` | 当前进程内 Tare 六轴偏置 | 1 Hz；标定采样时已记录 |
| `/ft_sensor/wrench_compensated` | 实验性重力补偿输出 | 当前因模型未通过独立验收而禁用；不得使用 |

## 架构边界

- `ati_netft_node.py` 是 ATI UDP 49152 的唯一消费者。
- 补偿节点只订阅 ROS 话题，不再访问 RDT，因此不会抢流。
- 物理标定必须使用 `/ft_sensor/wrench_raw`，并同时保存
  `/ft_sensor/software_bias`；不得使用无法追溯 Tare 状态的历史数据上线。
- 任何补偿模型都必须用未参与拟合的多姿态数据独立验收。

## 已验证的模型约定

TCP 轴角到旋转矩阵的方向已用独立姿态对比确认：重力向量从
`base` 变换到工具/传感器方向时使用 `R_base_tool.T @ g_base`。
反向 `R_base_tool @ g_base` 与真机数据明显不符。该结论只确认
坐标约定，不代表当前质量、重心或偏置参数可用。
