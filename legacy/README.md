# legacy —— 已废弃的"示教器 socket 方案"（留档）

这里的代码**不要用于新项目**，保留是为了记录踩过的坑和演进过程。

## 旧方案是怎么设计的

```
  电脑                                              UR 示教器
┌──────────────────────┐                      ┌────────────────────────┐
│ ur_pick_place_*.py   │  ① 机械臂运动        │ 通用执行器程序          │
│  ├ 30002 发 movel ───┼─────────────────────▶│  (读命令→rq_set_pos)   │
│  └ 监听 30010 ◀──────┼──② 夹爪执行器连入────│  socket_open(30010)    │
│     发 grip/release ─┼─────────────────────▶│  rq_set_pos(255/0)     │
└──────────────────────┘                      └────────────────────────┘
```

文件对应关系：

| 文件 | 作用 |
|---|---|
| `ur_pick_place.py` / `_cycle.py` | 早期版本：电脑起 30010 服务器，示教器作为客户端连入 |
| `ur_pick_place_drive.py` / `_hybrid.py` | 驱动版：30002 管臂 + 30010 管夹爪混合 |
| `ur_gripper_server.py` / `socket_test_server.py` / `ur_socket_server.py` | 各种测试服务器（诊断 socket 通不通） |
| `pickplace_observer.py` | 观察示教器程序有没有真的在抓放 |
| `pendant_*.urscript` | 贴在示教器上的程序（通用执行器、夹爪服务器、抓放循环） |
| `演示操作手册.md` | 当时的操作手册 |

## 为什么放弃

1. **`rq_activate()` 死锁** —— 它的等待循环 `while(ACT!=0 or STA!=0)` 在夹爪本来就
   `ACT=1` 时永远出不去。程序卡死，表现为"30010 能看到机器人连入，但发命令永远没回执、
   连接也不断开"。详见 [`../docs/04-夹爪控制.md`](../docs/04-夹爪控制.md)。
2. **URCap 往程序里塞 76KB 代码** —— 安装节点生成的 `def rq_*` 函数库、真空检测线程等，
   手工粘贴极易把残留代码一起带进去。
3. **Script 节点的 `cachedContents` 缓存** —— `.urp` 里存着一份脚本缓存，
   你更新了 `.script` 文件，程序跑的却还是旧缓存。（见 [`../docs/07`](../docs/07-机器人内部访问.md)）
4. **每次改代码都要重播程序**，socket 只能 open 一次，迭代极慢（改一行等一分钟）。
5. **故障点翻倍** —— 网络、示教器状态、URCap 干扰、socket 时序，任何一环都能让你白忙半天。

## 新方案（本仓库正文）

```
  电脑                                    机器人
┌────────────────────┐                ┌──────────────────┐
│ ur_arm.py ─────────┼── 30002 ──────▶│ URControl        │→ 机械臂
│ rq_gripper.py ─────┼── 63352 ──────▶│ drivergripper    │→ 夹爪
└────────────────────┘                └──────────────────┘
       示教器全程不参与
```

- 夹爪：电脑**直连**机器人上的 `63352`（Robotiq 守护进程，IPv6 通配监听，对局域网开放）；
- 机械臂：ROS 话题 `/ur_link/urscript` → 30002；
- 改代码**不用重播程序**，迭代以秒计。

见 [`../docs/04-夹爪控制.md`](../docs/04-夹爪控制.md) 与 [`../docs/05-完整抓放.md`](../docs/05-完整抓放.md)。
